## What happened

The Phase 1 acceptance gate is `scaffold/tests/verify_synthetic_harness.py`. It
invokes the universal pipeline orchestrator as:

    python3 scaffold/pipeline/build_leads.py --synthetic

with **no `--county-config` argument** (verify_synthetic_harness.py line 42).

`build_leads.py` declares its `--county-config` argument with a hardcoded
default (build_leads.py lines 723–724):

    parser.add_argument("--county-config",
                        default="config/counties/bexar_tx.json",
                        help="Path to populated county config ...")

`config/counties/bexar_tx.json` does not exist in this Greene County repository
(only `greene_ny.json`, `_template.json`, and `_schema.json` are present).
`build_leads.py` `main()` checks for the config file and exits 2 when it is
absent. Observed output:

    county config not found: .../config/counties/bexar_tx.json
    [FAIL] pipeline exited with code 2
    verify_synthetic_harness.py exit code: 1

## Root cause

**Pre-existing v5.3.0 known issue** — `VERSION_NOTES_v5.3.0.md`, section
"Known Issues — Deferred to v5.3.1", item 1 (`_state`-suffix slug pattern blind
spot):

> "Hardcoded county slugs in `scaffold/ops/verify_live.py`,
> `scaffold/ops/write_county_config.py`, and other ops files are not currently
> caught by the scanner. Pre-existing as of v5.2.0; not introduced by v5.3.0."

`scaffold/pipeline/build_leads.py` carries the same class of defect: a
hardcoded `bexar_tx` county slug as the `--county-config` default. This is a
framework-universal file. The defect was introduced before this build and is
not specific to Greene County — it would halt any county whose slug is not
`bexar_tx` at the Phase 1 verifier.

## Why no inline fix was applied

An inline fix was NOT authorized, for three reasons:

1. **Operator directive.** The operator explicitly instructed, at REVIEW_GATE_1,
   to halt cleanly per the Duval halt protocol rather than authorize an inline
   fix — to preserve the integrity of the parallel v5.3.0 client-experience
   test (Duval County halted at this identical point).
2. **Universality / scope boundary.** `scaffold/pipeline/build_leads.py` is a
   universal framework file. The Phase 0 launch contract
   (`runs/greene_ny/LAUNCH_GREENE_NY.md`) and MASTER_PROMPT §4.31 forbid this
   build from patching `scaffold/`. A county build does not modify the
   framework.
3. **Correct owner.** The fix belongs to the **v5.3.1 framework patch cycle**,
   which `VERSION_NOTES_v5.3.0.md` already designates as the owner of this
   class of issue.

## Operator action required (build does not auto-resume)

To resume Greene County at Phase 1, the operator must clear the framework
defect via one of:

1. **Apply the v5.3.1 fix** — parameterize `build_leads.py` so `--county-config`
   has no hardcoded county default (e.g. require the argument, or default it
   from a slug/env), and/or have `verify_synthetic_harness.py` pass
   `--county-config config/counties/greene_ny.json` explicitly. This is a
   framework patch, performed in the framework repo, not in this county build.
2. **Authorize a scoped exception** — explicitly instruct this build to pass
   `--county-config config/counties/greene_ny.json` (and to accept that the
   shipped `verify_synthetic_harness.py` would still need that argument
   threaded through). This deviates from the Duval parallel and should be a
   conscious operator decision.

Recommended: option 1 (v5.3.1 framework patch), consistent with the Duval halt
and with `VERSION_NOTES_v5.3.0.md`.
